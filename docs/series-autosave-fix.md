# 段階5・Gutenberg自動保存のローカル修正

2026年10月25日。`series-stage5.md`の本文だけが自動保存される問題を修正し、隔離WordPressで検証しました。本番への反映は行っていません。段階5は引き続き未完了です。

## 原因と修正範囲

WordPress 7.1.3の`class-wp-rest-autosaves-controller.php:238`以降は、本人の下書き・自動下書きに他者の編集ロックがない場合、親投稿を直接更新します。一方、Gutenbergの自動保存リクエストには、独自RESTフィールド`ojlSeries`が標準では含まれません。通常保存だけを囲む既存のトランザクションでは、この後続更新を防げませんでした。

| 経路 | 変更前 | 変更後 |
| --- | --- | --- |
| 下書きの明示保存 | 本文と連載設定を同時に保存・拒否 | 維持します |
| 本人の下書きへの自動保存 | 本文だけが更新され、連載設定が古いまま残る | 現在の設定を同送し、本文と設定を同時に保存・拒否します |
| 連載なしの通常記事 | 標準の自動保存 | 維持し、連載メタ・独自ロックを作りません |
| 公開・予約・承認待ち・非公開記事 | 自動保存リビジョンを作成 | 維持し、親の本文・連載設定を変更しません |
| 他者の下書き・他者の編集ロックあり | 自動保存リビジョンを作成 | 維持します |

PHPだけではブラウザー内の未保存設定を知ることができません。保存済みメタで検証すると、未保存の所属変更や回番号重複を見逃します。そのため、編集画面の既存スクリプトに`wp.apiFetch.use()`を追加し、編集中の投稿の`POST /autosaves`だけへ最新の`ojlSeries`を添えます。他の投稿・通常保存・別APIのリクエストは変更しません。

PHPではコアと同じ「親の下書きを直接更新する条件」に限定して、既存の`ojl_series_rest_save_request()`を再利用します。認証・編集権限・RESTスキーマ検証は標準処理を維持します。自動保存の成功時は本文と設定をコミットし、検証・本文保存・応答準備が失敗した場合はロールバックしてキャッシュ・通知待ち行列・保存ロックも戻します。

Gutenbergの自動保存ロックは追加していません。`editor.js:7084`の`isEditedPostAutosaveable()`はロックを確認し、同ファイル`:79051`の`__unstableSaveForPreview()`もこの判定を使うため、単純なロックは標準プレビューまで止める可能性があります。コアの保存アクションやセレクターの上書きは不要でした。

## 別件：ACF Warning

段階5の`Undefined array key "_name"`は、既存バックアップ内の`advanced-custom-fields-pro/pro/fields/class-acf-field-repeater.php:428`の`format_value()`で、repeater子フィールドの`$sub_field['_name']`を参照する箇所に対応します。直接原因は、その子フィールド配列にACF内部キー`_name`がないことです。直前には`name`・`key`を使う処理がありますが、`_name`の存在確認はありません。

どのフィールド定義・ロード処理・フィルターが欠落を起こしたかは、既存ログとこのソースだけでは特定できません。連載メタはACFを使用しておらず、自動保存の本文だけが更新される原因とは分けて扱います。ACFのコード・フィールド定義・DBは変更していません。
