# `/oyako-brands/`の独立HTML配信

最終調査日: 2026年10月28日。SSH・HTTP・GitHubはいずれも読み取りのみです。本番の変更・デプロイ、Actions起動、コミット・pushは行っていません。認証情報は記録していません。

## 結論と404の原因

**配置済みディレクトリが単数形の`oyako-brand`で、目的URLの複数形`oyako-brands`と一致していません。** 正しいディレクトリへHTMLを配置すれば、現在の本番設定のままで配信できます。

本番で確認した公開ルートは`~/oyakonojikanlabo.jp/public_html`です。`~`は既存SSH接続のホームディレクトリです。接続アカウント名や鍵のパスを転載しないため、この表記にしています。

| 本番の実ファイル                                                    | 確認結果                                                  |
| ------------------------------------------------------------------- | --------------------------------------------------------- |
| `~/oyakonojikanlabo.jp/public_html/.htaccess`                       | 存在。274,508バイト、0644                                 |
| `~/oyakonojikanlabo.jp/public_html/index.html`                      | React入口。公開URLの`/`・`/index.html`とSHA-256一致       |
| `~/oyakonojikanlabo.jp/public_html/oyako-brands/`                   | 存在しない                                                |
| `~/oyakonojikanlabo.jp/public_html/oyako-brand/index.html`          | 存在。1,249バイトの準備中HTML。ディレクトリ0705・HTML0604 |
| `~/oyakonojikanlabo.jp/public_html/lp/sunsunkidsvillage/index.html` | 存在。公開LPとSHA-256一致                                 |

公開先の`realpath`と実ファイルをSSHで確認し、React入口・LP・準備中HTMLの3種類を公開HTTPとハッシュ照合しました。ApacheのVirtualHost設定自体を閲覧したわけではありませんが、この対応から公開先を確認しています。ホームとドメインディレクトリ直下に親の`.htaccess`はありませんでした。

| 公開URL                                    | HTTP | 返却内容      |
| ------------------------------------------ | ---- | ------------- |
| `/oyako-brand/`・`/oyako-brand/index.html` | 200  | 準備中HTML    |

| `/oyako-brands/index.html`                 | 200  | React入口HTML |
| `/lp/sunsunkidsvillage/`                   | 200  | 独立LP        |

`/oyako-brands/`は実在ディレクトリ判定を通らず、単一階層URLの404規則と`ErrorDocument 404 /index.html`でReact入口を返しています。`/oyako-brands/index.html`は実在ファイルがなく、複数階層URLのSPAフォールバックで入口を返します。React専用の仮ページ追加は不要です。

## 本番との差分と前回修正の再評価

本番にはOJL管理マーカー、`/lp/`の先頭除外、実在ファイル・ディレクトリの通常配信、記事・連載の静的HTML配信、Reactフォールバックが既にあります。生成済み301は`Redirect 301`が94本と`RewriteRule`が7本、410は`[G]`の`RewriteRule`が1,034本です。条件付き規則も含むため、対象URL件数ではありません。

調査時の本番`.htaccess`のSHA-256です。

```text
267b657dc5b462fc6b02602807e74bf313747acb336ef26f93a62d66d8d05387
```

CMS生成のURLライフサイクルブロックを除くと、本番とローカルの差は前回の除外1行と説明コメントだけでした。生成ブロックは本番にだけ実際の301・410が入っています。**ローカルの`.htaccess`を直接コピーすると生成済みルールを失うため、本番へ置換してはいけません。**

| 前回の変更                        | 再評価                                                                                                                                 |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `.htaccess`の`/oyako-brands/`除外 | 今回の404解消には不要です。将来CMSと同名URLが衝突することを防ぐ目的では有効です                                                        |
| Viteの静的HTML配信拡張            | ローカル開発・プレビュー用。本番表示には不要です                                                                                       |

接続済みGitHubツールで現在のmainを読み取りました。`scripts/deploy-production.mjs`はルート同期に`--exclude=*/`を付け、ルートでは削除同期をせず、削除を管理対象ディレクトリ内部に限定します。`oyako-brands`は管理・削除対象に含まれません。前回の保護変更はmainにまだ含まれていませんが、現行mainの同期引数によるローカルrsyncでも原本・独自ファイルが保持されました。

ローカル作業ツリーには別改修が混在しています。一方、本番と現在のmainには連載用ディレクトリ・配信規則が既にあり、単に連載名の差分を全削除すればよい状態でもありません。今回はReactのビルド・一括同期を行わず、他機能の公開状態を保持します。
