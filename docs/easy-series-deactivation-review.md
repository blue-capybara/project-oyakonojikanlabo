# 旧Easy_Seriesの無効化に関する調査・判断

2026年10月25日。本番の現行コード・DB・配信HTML／JSONを読み取り調査しました。**無効化は可能と判断しますが、公開5記事のタイトルと旧連載目次が変わるため、その表示を維持する準備を条件に推奨します。削除・アンインストールは推奨しません。**

今回は無効化・削除、投稿更新、本番反映、Webhook／Actionsの再開を行っていません。WordPress全体をCLI起動せず、DBは読み取り専用トランザクションで確認しました。

| 対象 | 調査結果 |

無効化すると旧管理メニュー「連載」、旧記事編集用の所属設定欄、旧タイトル・目次・保存フックが登録されなくなります。これまでの空ID SQLや専用項目不足Warningの原因処理も実行されなくなる見込みです。これはコードからの判断であり、本番で無効化して検証した結果ではありません。

## データ保持と削除処理

旧`series_contents`はEasy_Seriesの専用テーブルとは別の仕組みです。本番DBのCPT UI設定に登録され、対象投稿タイプは`post`と`dino-pedia`です。現在25ターム、189関連があります。Easy_Seriesにはタクソノミー登録・削除処理がなく、無効化してもCPT UIによる登録、ターム・関連付け・画像等のメタデータは維持される構造です。旧テンプレートもこのタクソノミーを使用します。

| 操作 | コードで確認した挙動 |
| --- | --- |
| 無効化 | Easy_Series自身の無効化フックはありません。WordPressの`wp-admin/includes/plugin.php:762–854`は有効プラグイン一覧を更新し、無効化フックを呼びます。`uninstall.php`は呼びません。専用2テーブル・記事・旧タクソノミーは残ります |
| 再有効化 | `easy-series.php:17,61–73`の有効化処理は、専用テーブルがなければ作成します。既存のテーブルがあれば作り直しません |
| 管理画面の「削除」等によるアンインストール | `uninstall.php:10–18`が専用2テーブルの`drop_table()`を呼ぶ構造です。データ保持の目的と両立しません |

さらに`uninstall.php:2`は連載本体用DBクラスしか読み込んでおらず、`:16`で使う所属用クラスの読み込みがありません。実行経路によっては、最初のテーブルを削除した後にエラーとなる可能性もあります。削除処理は実行していません。

専用テーブルに外部キーによる連鎖削除や関連トリガーは確認されませんでした。無効化後もデータを保管し、テーブル整理・プラグイン削除は別案件としてください。

## 推奨する安全な手順（今回は未実施）

1. **5記事の表示維持案をローカルで準備します。** 現在の加工タイトルを通常の投稿タイトルとして持たせ、末尾の連載案内を通常の本文ブロックに置き換える案が最小です。既存本文のブロック構造とスラッグは維持し、GraphQLの描画済み本文全体をそのまま上書きする方法は使いません。145件の`gone`記事や旧データ全体の移行は不要です。
2. 旧目次は公開対象外の記事名も表示する実装です（`easy-series.php:758–802`）。固定する案内は公開済み記事へのリンクを基本とし、非公開回の正式タイトルを機械的に転記しない方針で内容を確認します。
3. 実施許可後、編集・予約公開と重ならない時間を決め、Webhook／Actionsの停止を再確認します。最新DB全体、専用2テーブル、プラグイン一式、5記事の変更前データ、有効プラグイン一覧、現配信HTML／JSONをバックアップし、復旧手順を確認します。
4. **Easy Seriesだけを通常の管理画面操作で無効化します。「削除」は押さず、ファイルも残します。** 無効化後のAPI変化を確認し、準備した5記事だけを通常記事データへ補正します。プラグインが有効なまま補正すると二重タイトル・二重目次になり得るため、順序を守ります。この作業時間中は動的APIで表示差分が出る可能性があります。
5. 5記事と一般記事、新連載の保存・再編集・重複拒否・標準プレビュー、旧タクソノミー、URL、SEO、PHPログを確認します。旧連載テーブルの件数・ハッシュが不変であることも照合します。本番フロントの更新は別途承認後に既存の全件ビルド手順で行い、今回は行いません。
6. 問題があれば停止し、対象5記事を変更前へ戻してからEasy Seriesだけを再有効化します。記事補正後にプラグインだけ戻すと、加工が二重になるため組合せで復旧します。他プラグインの状態やDB全体を機械的に巻き戻しません。

タイトル末尾・旧目次の撤去を許容する方針であれば5記事の補正は省けますが、表示・SEOの変更が残ります。今回の「既存機能を維持する」条件では、5記事の表示維持を準備したうえでの無効化を推奨します。
